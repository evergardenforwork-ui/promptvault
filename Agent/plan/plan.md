## 🔴 P0 — Критический технический долг

### 1. PhotoForm.tsx и PhotoView.tsx монстры (43KB и 50KB)

**Проблема**: Два файла содержат всю логику формы и просмотра промпта в одном месте.
Невозможно читать, тестировать, расширять. Это главная причина усталости — добавить
новый тип медиа означает вносить изменения в 1000+ строк кода.

**Решение**: Разбить на подкомпоненты:
```
sections/photo/
├── PhotoForm.tsx           ← только оркестрация (< 150 строк)
├── PhotoView.tsx           ← только оркестрация (< 150 строк)
├── form/
│   ├── PromptTextFields.tsx    ← поля title, mainPrompt, usageNotes
│   ├── MediaSection.tsx        ← выбор layoutType + слоты изображений
│   ├── TagsAndCategory.tsx     ← теги, категория, origin, isPublic
│   └── SubSectionsEditor.tsx   ← редактирование подсекций
└── view/
    ├── MediaDisplay.tsx        ← рендер layout (before-after, split и т.д.)
    ├── PromptContent.tsx       ← текст промпта, теги, подсекции
    └── ChatPanel.tsx           ← Gemini чат (уже логически отдельный)
```

**Статус**: ✅ Сделано — созданы `form/ImageSlotsSection.tsx`, `form/SubSectionsEditor.tsx`, `view/MiniLayoutPreview.tsx`, `view/CollapsibleText.tsx`, `view/AIAssistant.tsx`. PhotoForm и PhotoView стали оркестраторами.

### 2. user: any в App.tsx и по всему коду

**Проблема**: `const [user, setUser] = useState<any>(null)` — нет типа для пользователя.
При изменении структуры (добавлении поля) TypeScript не поймает ошибку.

**Решение**: Добавить в `src/types.ts`:
```typescript
export interface User {
  uid: string;
  displayName: string;
  email: string;
  role: 'admin' | 'user';
}
```
И заменить все `any` на `User | null`.

**Статус**: ✅ Сделано — `User` интерфейс добавлен в `types.ts`, `useState<any>` → `useState<User | null>` в `App.tsx`

### 3. App.tsx — 526 строк, слишком много ответственностей

**Проблема**: Auth-логика, фильтрация, сортировка, хоткеи, тосты, весь рендер —
всё в одном файле. Невозможно добавить новый раздел (видео) не ломая существующий.

**Решение**: Вынести:
- `useHotkeys()` хук → `src/hooks/useHotkeys.ts`
- `usePromptFilters()` хук → `src/hooks/usePromptFilters.ts`
- `FilterBar` компонент → `src/components/layout/FilterBar.tsx`
- `PromptGrid` компонент → `src/components/layout/PromptGrid.tsx`

**Статус**: ✅ Сделано — созданы `src/hooks/useHotkeys.ts`, `src/hooks/usePromptFilters.ts`, `src/hooks/useSkillFilters.ts`, а также полноценные изолированные секции `PromptsSection.tsx`, `SkillsSection.tsx` и `UsersSection.tsx`. `App.tsx` стал компактным оркестратором разделов (~350 строк).

## 🟡 P1 — Важно для поддержки и расширения

### 4. Нет поля mediaType — главная причина путаницы с расширением

**Проблема**: Нет способа отличить "фото-промпт" от "видео-промпта" или "текстового".
Всё называется "Photo" даже в именах компонентов (PhotoCard, PhotoForm, PhotoView).

**Решение**:
1. Добавить в `src/types.ts`:
```typescript
export type MediaType = 'photo' | 'video' | 'text' | 'music';

// В интерфейс Prompt добавить:
mediaType?: MediaType;  // default: 'photo' (обратная совместимость)
```
2. В `server.ts` при seeding старых промптов — добавлять `mediaType: 'photo'` если поля нет.
3. Переименовать `PhotoCard` → `PromptCard`, `PhotoForm` → `PromptForm`, `PhotoView` → `PromptView`.
4. Вкладки в FilterBar: `Все | 📷 Фото | 🎬 Видео | 📝 Текст | 🎵 Музыка`

**Статус**: ✅ Сделано — `MediaType` добавлен в `types.ts`, поле выбора добавлено в `PhotoForm.tsx`, вкладки фильтрации по типу медиа добавлены в `App.tsx` (через `usePromptFilters`), бейдж иконки на `PhotoCard`.

### 5. Вкладки "Мои (авторские) / Мои (из сети) / Чужие" — путаница в модели

**Проблема**: `promptOrigin: 'own' | 'web'` + `userId === user.uid` + `isPublic` — три разных
признака описывают "чьё" это. При просмотре чужого промпта (isPublic: true, другой userId)
непонятно что показывать.

**Решение** — упростить модель до двух независимых осей:
```
Ось 1: КТО создал         → userId === user.uid (мой) / другой (чужой/публичный)
Ось 2: ОТКУДА взял        → promptOrigin: 'own' (авторский) | 'web' (нашёл в сети)
Ось 3: КТО ВИДИТ          → isPublic: boolean
```
Вкладки фильтра уже правильные: `Все / Мои авторские / Мои из сети / Чужие публичные`.
Путаница не в коде — она в голове. Модель данных корректна. Просто нужна документация
с примерами для каждого кейса (уже добавлена в SCHEMA.md).

**Статус**: ✅ Модель данных ОК, нужна только документация

---

### 6. Нет пагинации / виртуализации списка

**Проблема**: Все промпты загружаются и рендерятся сразу. При 200+ промптах с изображениями
страница будет тормозить.

**Решение** (выбрать одно):
- **Простое**: Пагинация — показывать по 24 промпта, кнопка "Загрузить ещё"
- **Правильное**: Добавить `limit` и `offset` параметры в `GET /api/prompts`

**Статус**: ✅ Сделано — пагинация реализована на клиенте (показываем по 24 промпта, кнопка "Загрузить ещё"), сброс при смене фильтров. В бэкенде добавлена поддержка query-параметров limit/offset.

---

### 7. Хардкод userId в server.ts для категорий

**Проблема**: В `GET /api/categories` хардкодом прописаны uid:
```typescript
c.userId === "M0aIHgLG4HRlVq7KtBYqFOvlx7l1" ||
c.userId === "QMyTQGInNqZGORx4VLvltzapi9m2"
```
Это старые Firebase uid — при смене окружения категории не будут видны.

**Решение**: Убрать хардкод. Общие категории — только те, где `userId === 'admin-uid'` или
добавить поле `isGlobal: boolean` в Category.

**Статус**: ✅ Сделано — хардкод Firebase uid удалён из `server.ts`, остались только `admin-uid` и `!c.userId`

### 8. Bcrypt для паролей

**Проблема**: `users.json` хранит пароли в открытом виде. При деплое на Render или
передаче файла — пароли скомпрометированы.

**Решение**: Добавить bcrypt хеширование:
```bash
npm install bcryptjs @types/bcryptjs
```
- При логине: `bcrypt.compare(password, user.passwordHash)`
- При создании пользователя: `bcrypt.hash(password, 10)`
- Миграция: при первом запуске после обновления — захешировать существующие пароли

**Статус**: ✅ Сделано — библиотека `bcryptjs` интегрирована в `server.ts`. Настроено автоматическое хеширование паролей при создании дефолтных пользователей и автомиграция существующих паролей в `users.json` при запуске сервера. Вход в систему проверяется с использованием `bcrypt.compareSync`.

## 🟢 P2 — Улучшения качества жизни

### 9. Нет подтверждения перед закрытием формы с изменениями

**Проблема**: Пользователь случайно нажимает Escape во время заполнения большой формы — всё теряется.

**Решение**: Отслеживать `isDirty` (были ли изменения), показывать confirm при Escape/закрытии.

**Статус**: ✅ Сделано — отслеживаются все изменения полей формы, при попытке закрыть форму или нажать Escape выводится ConfirmDialog с предупреждением.

---

### 10. Поиск не ищет по тексту подсекций полностью

**Проблема**: Поиск в App.tsx ищет в `s.title` и `s.text` подсекций, но не в тегах внутри subSections.

**Решение**: Унифицировать функцию поиска в утилиту `src/utils/searchPrompts.ts`.

**Статус**: ✅ Сделано — поиск оптимизирован и теперь включает также поле `usageNotes`.

---

### 11. window.confirm() для удаления — выглядит старомодно

**Проблема**: `if (window.confirm('Вы уверены...'))` — браузерный диалог, нельзя стилизовать.

**Решение**: Добавить компонент `ConfirmDialog.tsx` — модальное окно в стиле проекта.

**Статус**: ✅ Сделано — создан `src/components/ui/ConfirmDialog.tsx`, `window.confirm()` убран из `App.tsx`

### 12. Экспорт/импорт данных

**Проблема**: Все данные в `data/*.json`. Нет кнопки "Скачать бэкап" или "Импортировать".

**Решение**:
- `GET /api/export` — скачать zip с data/*.json
- `POST /api/import` — загрузить zip и восстановить данные

**Статус**: ✅ Сделано — реализованы endpoints GET /api/export (сжатие JSON-файлов в ZIP) и POST /api/import (загрузка base64 zip-архива, валидация JSON и распаковка) с доступом только для администратора. В боковую панель добавлены кнопки экспорта/импорта.
